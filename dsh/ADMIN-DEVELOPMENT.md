# 管理员开发模式

## 入口与操作

管理员登录后默认显示研究任务。左栏的“创造任务”在同一工作台主区域打开原生创造界面，不跳转到另一套页面；“GeoSentinel 开发”下显示开发历史。新建创造任务默认使用 GeoSentinel 源码目录和 DSH 自带的 cordis 创造预设。研究对话不会因为切换视图而获得开发权限。

首次进入或授权过期时再次确认管理员密码。切换研究/创造视图保留已加载的开发界面和未发送草稿；刷新整个网页仍遵循原生草稿保存规则。普通用户没有这些入口，后端也拒绝调用。

创造界面首次初始化为空白任务时，优先定位产品源码根目录（本机 2026-09-12 起为 `E:\GeoSentinel\project`，旧路径 `D:\GeoSentinel-DSH` 保留为目录联接），不沿用其他工作区的最近空白任务。已经有内容的历史任务保留原目录。“添加工作区”复用 DSH 原生目录浏览、路径输入、新建文件夹和取消流程，仅把未指定的起始目录设为产品源码；显式选择其他目录仍然有效。该默认值来自服务端部署路径，不硬编码某台电脑的盘符。

目录选择界面通过 DSH 的目录选择插槽接入，复用原生目录读取、创建目录和工作区登记 API，并提供资源管理器式盘符导航、地址栏与上级目录。这里选择的是**服务器目录**，不会在服务器桌面弹出系统窗口。普通用户的附件按钮则通过浏览器文件输入控件打开**用户本机**的系统文件选择窗口，将选中的文件上传至其当前项目；支持多选，单文件上限为 16 MiB。

管理员可以使用原生标准/创造模式、模型设置、插件列表和配置、主题设置、文件浏览及主机执行。原生“完全权限”确认流程保留；这不是普通用户 Docker 沙箱。选择项目源码目录作为开发工作区，才是在修改 GeoSentinel；不要把运行数据目录当作项目源码。

GeoSentinel 的 platform、research、workbench 插件在开发进程内采用开发适配：研究工具使用独立验证工作区，界面保留原生设置和对话，普通用户平台的全局工具拦截不施加到该进程。专用 GIS 工具仍使用自身的容器执行约定；管理员可通过原生主机工具进行不受普通账号平台配额约束的开发操作。

## 两种管理员入口

平台内“开发模式”与独立命令 `geosentinel admin` 是两条并行入口，进程、home、profile 与插件集合都不同；同一台机器可以同时运行，互不替代。

| | 平台内开发模式（推荐） | 独立本机入口 `geosentinel admin` |
| --- | --- | --- |
| 前提 | 正式平台已运行且已登录管理员 | 不依赖平台进程 |
| 启动链 | 平台 `development/gateway.mjs` → `development/worker.mjs` → 原生 DSH | `cli/geosentinel.mjs admin` → `scripts/admin-start.mjs` → 原生 DSH |
| 监听 | 动态回环端口（`--port 0`） | 固定 `127.0.0.1:8514` |
| profile | `geosentinel-development` | `geosentinel-admin` |
| home | `GEO_DSH_HOME/development/<管理员ID>` | `GEO_ADMIN_HOME`，默认 `dsh/.runtime/admin-home` |
| 插件 | 开发源码的 platform、research、workbench、developer，加 Better Sidebar 与 Dream Skin | 只挂 `geosentinel-developer` |
| 授权 | 30 分钟密码再确认，绑定当前平台登录；降权、停用或退出即失效 | 无平台层授权，仅回环端口绑定 |
| 远程访问 | 经正式域名鉴权网关 | 仅本机 |

两条入口都加载产品源码，都不改写已发布的普通用户快照。

开发进程与独立入口本身都不提供 `/geo/api/*` 和 `/geo/native/`。产品配置、草稿导入、验证、预览和发布只存在于正式平台实例，因此发布必须回到平台界面完成，不能在开发界面里直接上线。

端口不要混淆：正式平台 8511，候选版本预览 8513，独立本机管理员入口 8514，开发进程为动态端口。判断当前处在哪个实例，看监听端口和进程的 `--profile` 参数即可。

做插件或产品源码修改，用平台内开发模式：它与草稿、预览、发布共用同一登录态。只有在平台未运行时才用 `geosentinel admin` 单独改代码，改动同样需要回到平台走发布流程。

## 发布边界

- 开发进程加载项目中的插件源码，不修改已发布的普通用户快照。
- “管理员设置”在当前主区域打开原生设置。调整模型、主题、字号或图片背景后，打开“产品配置与发布”，点击“应用开发设置到草稿”，检查显示内容，再保存产品配置、验证、预览、发布。导入本身不会上线。
- 首期同步已接入的 DeepSeek 模型、内置主题、14-24px 字号和不超过 2 MiB 的 PNG/JPEG/WebP 图片背景。外链、SVG、渐变与自定义主题不会静默转换，需要明确加入产品样式后验证。
- 角色工具、监测开关以及其他产品配置不会被导入的外观设置覆盖。密钥、完全权限、私人历史和无关设置不会进入草稿。
- 修改产品 UI、插件实现或产品 profile 后，通过验证、预览和显式发布使普通版更新。不会将管理员的整个 DSH home、密钥或完全权限复制到普通版。
- 原生设置中新增的任意第三方插件或模型供应商，不能直接承诺已兼容普通版；仍需加入产品依赖/profile、补充凭据引用并验证。当前并未实现任意原生设置的一键无差别迁移。
- 常见产品源码修改仍需要原生插件重载/开发进程重启，不能把刷新页面说成所有插件都能热更新。

## 普通模式能力管理

管理员模式的「设置 → 通用设置 → 普通模式能力管理」直接控制普通用户的能力边界，无需重新发布：

- 面板列出**已发布**的能力目录：研究主管工具、三个角色的工具、技能库；每个条目可在「常驻 / 禁用」之间切换，写入部署 home 下的 `capability-policy.json`（与普通版实例共读同一文件）。
- 策略**只能关闭发布快照里已有的能力，不能新增**：工具上限仍是平台允许列表，技能上限仍是随快照冻结的 `dsh/skills`。这是运行时收窄层，不是新的授权来源。
- 普通版实例每 5 秒检查该文件：工具在守卫处立即拦截（返回"该工具已被管理员在能力管理中关闭"），技能重新注册后从目录消失（`skill` 工具返回 unknown）。
- 面板与接口只在管理员开发进程内提供，仅回环访问；写入是管理员操作，随开发进程审计。
- 需要**新增**工具或技能时仍然走源码 + 验证 + 发布，不能用该面板绕过发布。

## 远程访问与权限

- 取消“仅本机管理员”的用户访问限制。仍需配置正式域名的 `GEO_ALLOWED_HOSTS`，公网使用 HTTPS。
- `/geo/development/` 的所有页面、文件、RPC 和已支持的 WebSocket 都经平台鉴权，原生 DSH Cookie 和启动 token 只保留在服务端。
- 再确认授权有效期为 30 分钟，绑定当前平台登录，另一个浏览器登录不会继承。退出、密码变更导致的登录撤销、停用账号和降权会使访问失效。授权过期不自动删除开发历史。
- 停用/撤销管理员角色会终止其开发进程；普通用户不允许访问开发 API，即使知道 URL。
- 开发者拥有服务主机账号的文件权限，进程分离不是针对管理员的安全沙箱。请只向可信人员授予管理员角色，并更换演示密码。代码不会擅自修改现有账号密码。
- 原生开发进程使用动态的回环端口，不能额外映射到公网。对外只映射 GeoSentinel 正式服务。
- 当前原生 RPC、多路流、Better Sidebar 终端与推送通道已接入；第三方插件新增专有 WebSocket 地址时需要在网关中显式接入，不能认为任意插件自动兼容。

## 配置与存储

- 每个管理员的 home：`GEO_DSH_HOME/development/<管理员ID>`。
- 开发验证文件与研究记录在自己的 home 内，与正式项目、账号数据库分开。
- 兼容保留 `geosentinel admin` 独立原生启动命令，但平台内“开发模式”不依赖这个实例。
- Windows 启动时探测 PowerShell 7 可执行性，跳过损坏的系统别名；必要时通过 `GEO_ADMIN_PWSH_PATH` 指定可执行文件。此配置只作用于平台启动的开发进程。
- 研究发布会等待普通任务和已运行的管理员开发任务结束；开发完成后再发布，不把发布作为终止任务的手段。

实现入口：`development/access.mjs`、`development/gateway.mjs`、`development/worker.mjs`、`plugins/developer/`。传输适配仅在管理员页面生效，不修改安装的上游 DSH 代码。


### 开发入口就绪判定

开发工作进程必须等 `sessionController`、`workspaceRegistry`、`fileUploads` 全部激活后才发送就绪消息；监听端口打开或通用插件加载完成不能代替会话能力就绪。避免首次进入时出现 `active Service "sessionController" is unavailable`。


DSH 0.1.5 自带 `file-upload` 条目。第三方 `dsh-file-upload` 在管理员 profile 中改用 `geo-file-upload` 条目加载，不能同时直接启用其同名 bundle。开发启动器会备份并迁移此冲突配置，保留插件、原生上传和会话数据。

旧 `@nanmicoder/dsh-agent-teams` bundle 不再挂入0.1.5管理员开发实例；启动器备份其配置后停用该旧bundle，保留安装文件与历史，使用DSH原生委派机制。
