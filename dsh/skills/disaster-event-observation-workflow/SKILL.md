# 灾害事件到观测的工作流

只做回答问题需要的步骤，验证到方案要求的产物即停止。

## 路由

- 只要事件上下文：只派事件助手。
- 事件 + 夜间灯光分析：事件助手 → 数据助手 → 分析助手；已有可用上下文或分析就绪观测时跳过相应角色并说明理由。
- 每个角色一个自包含任务：目标、已知来源或工作区输入、确切交付物、停止条件。

## 事件事实

- 记录来源、检索时间、发生时间、时区或"仅日期"语义、位置精度与 `as_of`。
- 保留冲突的时间/震级/位置/状态，不要选一个没有来源支持的折中值。
- 测试样例（fixture）必须显式标注为样例，不能当作真实事件证据。
- 事件事实只提供上下文，**不证明**灯光影响、损失、停运、责任或恢复。

## 观测选择

- 先确定产品、波段、产品日期语义、AOI、QA 规则、单位与 NoData 规则。
- 不要自行发明事件缓冲区、对照区或恢复窗口；用户明确要求缓冲区时记录中心、CRS、半径与理由。
- 缺测/有云/QA 不合格的夜次按缺测处理，不要插值成事件轨迹。

## 有界比较

- 只有来源时间线与合格观测支持时才定义事件前基线与事件/后续窗口；报告有效日数与覆盖。
- 变化只能表述为带 QA、季节、背景、空间尺度与覆盖限制的描述性观测。
- 完成主计算与一次相关验证后即交付，不重复成功过的检查。
