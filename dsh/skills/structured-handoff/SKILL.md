# 结构化交接

## 主管派活

- 只有主管分配工作；专家之间不互相派活，也不得自行扩大范围。
- 每个任务自带完整上下文：目标、科学范围（AOI、日期、单位、方法）、已知输入或工作区路径、要求的交付物（工作区相对路径）、验收标准、停止条件与已知限制。
- 不要依赖隐式上下文或让下游去猜；任务描述本身应当自洽到"另一个角色只看它就能开工"。
- 交付物是工作区里的文件（`outputs/...`）加一段说明；没有文件就明确说明这是总结性结果。

## 专家回传

返回时写清：

1. **状态**：完成 / 需要修订 / 阻塞（阻塞必须给出具体原因）。
2. **产物**：工作区相对路径与语义角色；没有产物就说明是总结性结果。
3. **基于证据的摘要**：数据来源、时间范围、方法、单位、有效像元或覆盖、关键数值。
4. **验证结论**：做了什么检查、结果如何。
5. **限制与不确定性**：缺测、覆盖缺口、替代解释。
6. **修订需求**：需要上游补什么、为什么。

## 边界

- 修订请求只回到主管；主管决定是否重派、是否收窄范围。
- 不要编造校验和、字节数、时间戳或运行标识——这些由平台记录。
- 不要把同一栅格的重复计算说成独立科学验证。
