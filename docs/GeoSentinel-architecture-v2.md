# GeoSentinel 四角色架构（Deep Agents 0.7.5）

## 目标

GeoSentinel 是地缘环境智能计算平台。夜间灯光是重要证据源之一，但不是产品身份，也不是所有任务的默认路径。新版架构按证据职责拆分角色，并通过类型化交接、角色级工具与技能权限、线程工作区和可审计产物约束复杂任务。

## 角色

| 用户名称 | 内部标识 | 主要职责 |
| --- | --- | --- |
| 地缘分析师 | `NTL_Engineer` | 任务定义、计划、路由、交接验收、证据综合和最终结论 |
| 数据助手 | `NTL_Data_Searcher` | 事件源、行政边界、遥感、Earthdata/GEE、气候、人口、基础设施与社会经济观测的获取、质量和溯源 |
| 分析助手 | `NTL_Analyst` | 时空、栅格/矢量、遥感解译、事件影响、生态气候、暴露、社会经济和可视化分析 |
| 事件助手 | `NTL_Event_Tracker` | 冲突、灾害、停电、事故、政策、物流与恢复事件的来源核验、时间线和来源冲突 |

三个专门角色不相互委派；地缘分析师按需串行调度，避免并发交接造成产物身份和任务状态竞争。

## 从参考框架吸收的能力

- Deep Agents 0.7.5、LangChain 1.3.15、LangGraph 1.2.11 依赖栈。
- 按角色划分的工具集合、技能命名空间和文件系统权限。
- `TaskPlan`、`EventContext`、`ObservationPackage`、`AnalysisPackage`、`EvidenceReport` 类型化契约。
- 系统绑定的本地文件身份、路由状态、转交记录和运行证据。
- 每线程 `inputs`、`outputs`、`memory` 工作区与只读 `/shared/` 数据。
- 适合简单任务的直接执行路径，以及面向复杂任务的按需专门角色路由。
- GEE 项目和认证由运行时统一解析，工具导入时不再主动认证。

## 平台默认规则

- 根据用户的问题选择证据，不强制进入夜间灯光流程。
- 默认使用数据产品的标准值。
- 角度、季节、辐射、跨传感器、大气、几何等校正或协调操作仅在用户明确要求，或用户明确指定的方法本身要求时执行；模型生成的计划不能自行授权校正。
- 用户可见角色名称不超过五个汉字；内部 `NTL_*` 标识仅为持久化和接口兼容保留。
- 正式入口是 `run_web.py`；Streamlit 仅用于内部诊断。
- 正式 Web 单次任务最多调用模型 50 次；达到上限后保留既有文件和记录，不自动重放整项任务。
- 用户可手动停止任务；同一监测案件在 10 秒内重复进入研判只响应一次。
- 监测案件先作为未核验线索帮助用户理解事件，再补充检索，最后给出分析方向、证据需求与判定条件。
