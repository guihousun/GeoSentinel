# 地缘环境智能计算平台 UI 规范

更新日期：2026-08-24

## 产品模板

正式界面采用任务式智能体研究工作台：研究问题、对话、空间证据、监测信息和文件产出围绕同一研究任务组织。地图是证据视图，不是 KPI 仪表盘或营销页。

## 页面骨架

- 认证与首用页：解释平台用途、清晰登录或注册入口、最少必要表单字段。
- 主工作台：左侧为任务与资料入口，中间为任务对话和流式运行信息，右侧为公共监测地图与监测队列。
- 地图专题页：突出研究问题、地图证据、专题分析入口和与该专题关联的对话；不复制主工作台的无关模块。

## 硬规则

1. 优先服务 `1366×768` 与 `1440×900` 桌面视口：首屏展示当前研究问题、主对话、主要地图或专题证据，以及下一步动作。
2. 小于 `1024px` 时收纳次要栏位，不能以横向滚动代替布局响应。
3. 中文为默认语言；仅在术语、来源名或专有名词需要时保留英文。
4. 任何“事件”“状态”“结论”均需有真实来源、时间或任务上下文；不展示虚构指标、确定性叙述或装饰性数据。
5. 信息层级仅保留主题、证据、行动三层；删除重复标题、未经确认的副标题和无任务意义的标签。
6. 地图必须说明当前范围、图层或来源；颜色不得单独表达严重性、状态或分类。
7. 文字和图标与背景至少满足可读对比；正文不低于 14px，紧凑标签不低于 11px，正文行高保持在 1.5 至 1.75。
8. 使用 4px/8px 间距节奏；卡片、按钮和面板尺寸稳定，不因状态文本变化而跳动。
9. 聊天气泡、队列行和证据卡按内容自适应高度；不得用容器余高拉伸短内容。
10. 加载、空、错误和完成状态必须给出清楚的下一步，不能只显示旋转图标或颜色。
11. 图标按钮必须有可访问名称和明显焦点态；用户可通过键盘完成任务、导航、收纳和提交操作。
12. 完成交付前检查桌面截图、文本对比、无横向溢出、控制台错误、空状态与真实数据状态。

## Skill 路由

1. `victor-design-system`：先确定交付形式、研究叙事、真实素材和视觉验收目标。
2. `ui-ux-pro-max`：再实施产品 UI、可访问性、响应式行为、交互和技术栈 QA。
3. `design-taste-frontend`：只用于未来营销官网、作品集或展示页；不用于研究工作台、地图、表格或多步骤研究流程。

## 验收清单

- 页面在常见桌面比例下主任务和主要证据无需向下滚动即可识别。
- 当前用户任务与全局监测明确区分，不能相互伪装或混合存储。
- 监测地图默认全球尺度；国家或专题页面默认研究区尺度。
- 重要动作有清晰文本或图标说明，主界面每屏只有一个主要行动方向。
- 真实来源不可用时显示降级或待同步状态，不以占位数据替代。
