# 地缘环境智能计算平台 UI 展示与使用说明

## 1. 本次展示的定位

这是一个面向国际地缘政治研究的桌面端工作台原型。它不是多个互不关联的页面，而是以同一研究线程为中心，把空间态势、智能体协作、证据材料和专题分析组织在一起。

本次展示由**三个一级研究空间**和**一个专题案例**组成：

- **全球态势**：默认工作台。以同一研究线程查看空间态势、发起问题，并由地缘分析师调度数据检索、知识补充和代码复核能力。
- **事件监测**：把公开事件、跨境风险和空间线索组织为可核验的研究任务；每个条目可直接带入主任务输入。
- **国家画像**：以国家尺度汇集政治安全、经济连接、社会民生和空间暴露的研究基线，并提供进入相关专题的入口。
- **缅甸粮食物流与可达性专题**：作为国家画像下的案例，而非另一套独立系统。它基于现有论文与支撑材料，将 Kaladan 走廊的节点、走廊、可达性和网络韧性证据组织为可直接提问的专题会话。

**证据档案不作为一级页面。** 它是任务、事件或专题结论的附属证据层：正式接入后会在结果旁按需展开来源、时间、空间范围、方法、置信度与人工核验记录。这样保留可追溯性，又避免出现一个脱离研究问题的孤立入口。

## 2. 主界面各部分含义

### 左侧栏：研究控制台

左侧栏既是导航，也是当前研究线程的控制台。它不再与页面中的第二套“研究入口”重复。

| 区域 | 含义 | 后续使用方式 |
| --- | --- | --- |
| 研究空间 | 切换“全球态势”“事件监测”或“国家画像”三个研究视角。 | 切换页面不会制造割裂的产品体系；正式接入后，仍与同一任务、证据链和智能体调度关联。 |
| 专题案例 | 进入已有方法、数据和结果支撑的深度专题。 | 当前为“粮食物流与可达性”；后续可并列增加能源通道、跨境流动、港口风险等专题。 |
| 当前案例 | 说明本次展示聚焦的研究对象。 | 当前为“缅甸西部粮食安全”，用于快速进入粮食物流专题。 |

“证据档案”不再作为一级研究空间。证据的正确位置是每项任务内部：某一事件、国家指标或专题结论旁边显示其来源、时间范围、空间范围、方法、置信度与人工核验状态。这样既保留可追溯性，也避免用户先进入一个没有研究问题的孤立档案页。

### 三个研究空间的分工

| 入口 | 要回答的问题 | 当前展示界面 | 正式接入后的产物 |
| --- | --- | --- | --- |
| 全球态势 | 当前哪些地区、事件和空间信号值得研究？ | 主工作台、全局地图、主对话与智能体看板。 | 跨区域态势图、任务简报、可继续追问的研究线程。 |
| 事件监测 | 哪些公开事件需要定位、核验并升级为研究任务？ | 全球监测地图与优先研判队列；点击“进入研判”即可将问题带入主对话。 | 带来源、时间、位置、置信度和核验记录的事件卡片。 |
| 国家画像 | 某国的结构性风险、连接条件和空间暴露如何？ | 缅甸一级行政区划地图、四维研究摘要与粮食物流专题入口。 | 可更新的国家研究基线、区域比较与专题输入。 |

### 中央区域：空间态势与对话

| 区域 | 含义 | 后续使用方式 |
| --- | --- | --- |
| 全球态势地图 | 在同一底图上汇集研究区域、事件和空间信号。 | 由事件数据、边界、遥感、人口、流动和专题结果图层驱动；时间轴用于筛选时段。 |
| 智能体对话 | 研究者输入问题、补充约束、查看任务回应的主入口。 | 接入 NTL-GPT 的主智能体图后，发送的内容将进入同一任务线程。 |
| 输入框 | 研究问题或专题参数的输入位置。 | 可输入区域、时间窗、事件来源、指标、情景假设和需要生成的结果。 |

### 右侧栏：智能体看板

| 角色 | 职责 | 触发条件 |
| --- | --- | --- |
| 地缘分析师 | 拆解任务、安排工具、汇总结论并保留证据链。 | 每个研究任务默认启动。 |
| 数据检索助手 | 获取事件、空间、社会经济和公开数据。 | 任务需要外部数据、边界或专题图层时启动。 |
| 知识库助手 | 补充理论、概念和现有工作流未覆盖的知识。 | 只有技能与已有证据不足时按需启动。 |
| 代码助手 | 对复杂的定制算法、脚本和结果做复核。 | 地缘分析师需要二次校验或研究者明确要求复核时启动。 |

看板不是第二个聊天窗口，而是主研究线程的过程反馈。正式接入后，它应订阅智能体运行事件，而不是由前端固定显示状态。

## 3. 缅甸粮食物流与可达性专题

### 专题页面的构成

| 区域 | 展示内容 | 面向的研究问题 |
| --- | --- | --- |
| 专题地图 | 默认聚焦缅甸全境，并以一级行政区划为基础参照，显示西部 Kaladan 走廊的节点、走廊和跨境接口。 | 在国家尺度定位生产源、转运节点、瓶颈点与替代入口。 |
| 空间证据图层 | 缅甸一级行政区划、节点网络、粮食生产强度、居民点分布、可达性成本表面。 | 三类基础栅格默认叠加，可独立开关，观察它们与走廊、节点和跨境接口的空间关系。 |
| 专题问答 | 同一研究线程内的专题对话入口。 | 直接提出节点失效、替代路径、粮食供给或可达性问题，而不是先阅读大段静态说明。 |
| 当前空间焦点 | 点击地图节点后自动更新的简短上下文。 | 把选中的节点和当前图层带入下一条问题，避免维护另一套固定节点面板。 |
| 论文案例参考 | 默认收起的归档案例说明。 | 仅在需要时查看“5% 节点移除后约 7% 连通分量保留”的对照基线；不把它误读为实时计算。 |

### 已有案例材料与结果

以下内容来自本项目已经归档的论文和支撑材料，可作为今晚展示的真实基础：

- **粮食生产强度**：SPAM 2020 栅格，约 10 km 空间分辨率。
- **居民点分布**：约 30 m 栅格，用于表征末端人口与聚落空间。
- **可达性成本表面**：约 30 m 栅格，用于估算走廊和服务范围。
- **缅甸一级行政区划**：geoBoundaries `MMR ADM1`，2019 年代表边界、14 个一级行政单元、CC BY 4.0；用于国家尺度空间参照，不参与案例指标计算。
- **研究框架**：节点—走廊—瓶颈点，结合网络中心性与可达性分析。
- **论文案例结果**：移除介数排名前 5% 的节点后，最大连通分量约为原网络的 7%，显示供应系统对少数关键转运节点高度敏感。

该结果以“论文案例结果”标注，表示已归档的研究结论，而不是本次页面实时重新计算的数值。

### 专题与智能体的关系

专题不应成为一套独立的聊天机器人。专题页右侧的问答窗口与主工作台共用**同一个研究线程**：

1. 用户在专题地图中选择节点、图层或空间范围。
2. 用户直接在专题问答中补充问题、时间窗、事件来源或情景假设。
3. 这些内容写入与主工作台一致的研究线程，而不是另起一个专题机器人。
4. 地缘分析师根据需要调度数据检索助手、知识库助手或代码助手。

这避免了专题页面与主研究任务之间出现两套上下文、两份历史记录和两种权限模型。

## 4. 今晚的演示路径

1. 打开 `index.html`，或在本目录运行静态服务后访问 `http://127.0.0.1:4173/`。
2. 先展示主工作台：左侧是研究空间和任务线程，中间是空间态势与主对话，右侧是智能体调度。
3. 点击左侧“粮食物流与可达性”，进入 `#logistics` 专题页。
4. 点击图层按钮，确认地图默认显示缅甸一级行政区划，以及“粮食生产强度”“居民点分布”“可达性成本表面”三类空间证据；可按研究问题独立开关任一图层。
5. 点击地图节点，再在右侧专题问答中提问，说明节点和图层会成为同一线程的空间上下文。
6. 按需展开“论文案例参考”，说明“5% → 约 7%”是归档研究的对照基线，不是当前的实时计算。
7. 点击“返回全球态势”，说明专题结果未来可作为全球工作台的一类证据图层和任务上下文。

## 5. 展示占位与正式接入的边界

为便于展示，当前原型包含地图节点、走廊线、智能体状态和任务状态等视觉样例。它们用于演示信息组织方式，不能被解读为实时的冲突判断、实时事件数量或已完成的自动计算。

正式接入时应保留如下原则：

- 每一项事件、风险或节点判断都附带数据来源、时间范围、方法和人工核验记录。
- 真实运行状态来自智能体事件流，而不是前端固定文本。
- 专题地图应加载当前任务的 GeoJSON、栅格或矢量切片，而不是示意坐标。
- 每一次专题计算都在当前任务工作区中读写，结果通过同一线程回传。

## 6. 后续接入方式

### 主工作台

| UI 入口 | 未来后端动作 |
| --- | --- |
| 主对话发送 | 调用地缘分析师主图，创建或续写当前任务。 |
| 智能体看板 | 订阅主图的节点事件，展示规划、检索、工具调用、复核和完成状态。 |
| 全球地图 | 读取经过权限和时间范围筛选的事件、空间证据和专题结果图层。 |
| 研究空间切换 | 更新当前任务的研究上下文，不丢失会话与证据链。 |

### 粮食物流专题

建议把专题封装为 `food_logistics_accessibility` 工作流，由同一个地缘分析师调用。输入可包括：

- 研究区或边界；
- 目标时间窗；
- 节点或走廊名称；
- 事件来源与过滤条件；
- 道路、通行限制和边境管制信息；
- 节点失效或替代走廊的情景假设。

预期输出包括：关键节点清单、走廊可达性/暴露地图、网络韧性情景表、替代路径建议，以及含数据来源和方法说明的证据简报。
